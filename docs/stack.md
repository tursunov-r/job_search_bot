# Технологический стек проекта

Этот файл — про то, на чём **написан сам бот** (инфраструктура проекта). Про то, вакансии на каких языках/фреймворках бот **собирает и присылает пользователям**, см. [`sources.md`](sources.md) и реестр `src/jobsbot/processing/languages.py` / `stack_tags.py`.

## Язык и база

| Компонент | Технология | Версия (из `pyproject.toml`) |
|---|---|---|
| Язык | Python | >=3.11 (образ собран на 3.12) |
| Telegram-бот (Bot API) | aiogram | 3.4–4.0 |
| Telegram-клиент (MTProto, для чтения каналов) | Telethon | 1.34–2.0 |
| Планировщик задач | APScheduler | 3.10–4.0 |
| HTTP-клиент | httpx | 0.27–1.0 |
| HTML-парсер (HH.ru, LinkedIn) | selectolax | 0.3–1.0 |
| ORM / модели / схема БД | SQLModel | 0.0.16–1.0 |
| Async-драйвер Postgres | asyncpg | 0.29–1.0 |
| Async-мост SQLAlchemy | greenlet | 3.0–4.0 |
| Миграции (объявлены, не используются — см. ниже) | Alembic | 1.13–2.0 |
| Конфигурация из `.env` | pydantic-settings | 2.2–3.0 |

## Хранилище

- **PostgreSQL** — единственная поддерживаемая БД (см. [`README.md`](../README.md#переменные-окружения) про переменные `DB_*`). Поддержки SQLite в проекте больше нет — конфиг не даёт дефолта на неё, только явные Postgres-секреты.
- Схема создаётся автоматически при старте (`SQLModel.metadata.create_all()` в `storage/db.py::init_db()`), миграций Alembic нет — при изменении полей моделей на уже существующей базе нужно либо накатывать `ALTER TABLE` руками, либо пересоздавать volume.

## Тесты

- `pytest` + `pytest-asyncio` — юнит-тесты на чистую логику (дедуп, фильтры, детект языков, парсинг сообщений). Запуск: `PYTHONPATH=src pytest tests/`.
- `respx` объявлен в dev-зависимостях для мока HTTP, но на момент написания живые проверки HTTP-адаптеров делались вручную (ad-hoc прогоны против реальных hh.ru/LinkedIn), а не через respx-фикстуры.

## Деплой

- **Docker** — `Dockerfile` на `python:3.12-slim` (официальный multi-arch образ, собирается и под amd64, и под arm64 — в том числе на Raspberry Pi).
- **docker-compose** — два сервиса: `bot` (сам бот) + `postgres:16-alpine`, с named volume для данных Postgres и bind-mount `./data` для Telethon-сессии (`.session`-файл должен переживать перезапуск контейнера).

## Архитектура источников вакансий

Все три источника (HH.ru, LinkedIn, Telegram-каналы) работают через **поллинг** — периодические задачи в одном `AsyncIOScheduler`, без постоянных event-driven подключений (кроме самого MTProto-соединения Telethon, которое держится открытым, но данные забираются по таймеру, а не через live-подписку на события).
