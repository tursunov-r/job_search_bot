# Источники вакансий

Бот собирает вакансии из пяти источников. Все работают через **поллинг** (периодический опрос), управляются одним `AsyncIOScheduler` в `src/jobsbot/main.py`.

## 1. HH.ru

- **Как собирается**: HTML-парсер страницы поиска `hh.ru/search/vacancy` (`src/jobsbot/ingestion/hh_adapter.py`) — **не официальный API** (он платный для такого использования), обычный HTTP-запрос с теми же параметрами, что видит браузер.
- **Описание и структурированные поля** (опыт, занятость, график, формат работы): страница поиска их не отдаёт — дотягиваются отдельным запросом на страницу вакансии (`fetch_vacancy_details`), но **только для новых** вакансий, прошедших дедуп и фильтр релевантности (чтобы не плодить лишние запросы на весь список выдачи).
- **Интервал**: `HH_POLL_INTERVAL_SECONDS` (по умолчанию 600с = 10 мин).
- **Языки**: отдельный поисковый запрос на **каждый** язык из реестра `processing/languages.py` (см. список ниже) — т.е. за один цикл поллинга бот делает N запросов к hh.ru, один на язык.
- **Легальность**: публичная HTML-страница, без логина, с паузами между запросами (`PAGE_DELAY_SECONDS`).

## 2. Хабр Карьера (career.habr.com)

- **Как собирается**: HTML-парсер страницы поиска `career.habr.com/vacancies` (`src/jobsbot/ingestion/habr_adapter.py`) — публично, без логина. `robots.txt` не запрещает `/vacancies` (запрещены только служебные под-пути типа `/vacancies/*/responses`) — риск сопоставим с HH.ru.
- **Зарплата**: на странице поиска два варианта — реально указанная (`.basic-salary`) или алгоритмическая оценка Хабра (`.predicted-salary`, "Зарплата не указана, похожие специалисты получают..."). Используется **только первая** — показывать алгоритмическую оценку как реальную было бы нечестно.
- **Опыт/локация/формат работы**: чипы на странице поиска, различаются по иконке (`icon-grade` → опыт/грейд Junior-Middle-Senior, `icon-placemark` → город, `icon-format` → "Можно удалённо").
- **Тип занятости/график**: не парсятся — на Хабре это есть только в SEO-тексте `<meta name="description">`, не в структурированной разметке, ненадёжно.
- **Описание**: дотягивается отдельным запросом на страницу вакансии, только для новых вакансий (как у HH).
- **Интервал**: `HABR_POLL_INTERVAL_SECONDS` (по умолчанию 600с = 10 мин).
- **Языки**: те же поисковые термины, что и для HH (`Language.hh_search_term` из общего реестра) — отдельный запрос на каждый язык.

## 3. Geekjob.ru

- **Как собирается**: HTML-парсер страницы листинга `geekjob.ru/vacancies` (`src/jobsbot/ingestion/geekjob_adapter.py`) — публично, без логина. `robots.txt` разрешает всё кроме `/json/` и `/rest/`.
- **Важное отличие от HH/Habr: поиск по ключевому слову (`qs=`) здесь целиком клиентский** — страница собрана на Vue (`/app/filters/vacancies/app.js`), который сам стучится в `/json/`/`/rest/`, запрещённые `robots.txt`. Обычный GET-запрос с `qs=python` отдаёт тот же самый неотфильтрованный листинг, что и без параметра (проверено живьём — 0 отличий в выдаче). Поэтому здесь **нет цикла по языкам**, как у HH/Habr: просто листается общая выдача (`MAX_PAGES`), а релевантность и язык(и) определяются из текста через `processing/languages.py::detect_languages()` — ровно так же, как для Telegram-каналов.
- **Зарплата/город/формат работы**: прямо на странице листинга (`div.info > span.salary`, текст перед `<br>` внутри того же `div.info`, бейджи `span.remote-label`/`span.inhouse-label`). Формат работы с листинга — это английские `remote`/`office` (переводятся в код сразу при парсинге); если оба бейджа присутствуют одновременно — значит вакансия гибкая по формату.
- **Описание + уточнённый формат работы/опыт**: дотягиваются отдельным запросом на страницу вакансии (`#vacancy-description`, `span.jobformat` — там уже по-русски, те же слова, что и у HH/Habr), только для новых вакансий, как у HH/Habr.
- **Интервал**: `GEEKJOB_POLL_INTERVAL_SECONDS` (по умолчанию 600с = 10 мин).

## 4. LinkedIn

- **Как собирается**: публичный неавторизованный "guest"-эндпоинт поиска вакансий (`src/jobsbot/ingestion/linkedin_adapter.py`) — без логина, без cookies/сессии.
- **Статус**: выключен по умолчанию (`LINKEDIN_ENABLED=false`). Самый изолированный и юридически рискованный источник в проекте — LinkedIn жёстче, чем hh.ru, борется со скрапингом. Включается одним флагом в `.env`, выключается так же мгновенно, не затрагивая остальные источники.
- **Интервал**: `LINKEDIN_POLL_INTERVAL_SECONDS` (по умолчанию 3600с = 1 час) — заметно реже HH, плюс случайные задержки и экспоненциальный backoff между запросами.
- **Языки**: только Python (`language_hint="python"` жёстко зашит в `main.py::poll_linkedin()`), мультиязычность на LinkedIn не распространяется — осознанное ограничение скоупа.
- **Описание**: не дотягивается (в отличие от HH) — фильтр по стеку для LinkedIn-вакансий работает только если технология упомянута в заголовке.

## 5. Telegram-каналы

- **Опционально**: целиком отключено, если в `.env` не заданы `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` (получение этих значений с my.telegram.org иногда капризничает — ошибка при создании приложения, региональные блокировки и т.п.). HH.ru и LinkedIn работают независимо от этого.
- **Как собирается**: `src/jobsbot/ingestion/telegram_poller.py`, через Telegram **user-аккаунт** (библиотека Telethon, MTProto) — обычный бот не может сам вступать в чужие публичные каналы, поэтому используется отдельная авторизация по номеру телефона (один раз, создаёт `.session`-файл).
- **Список каналов — хранится в БД**, не в `.env`. Управляется через `/admin` → "📡 Каналы" (см. [`admin.md`](admin.md)) — добавление/удаление происходит без передеплоя и подхватывается на следующем цикле поллинга.
- **Интервал**: `TELEGRAM_POLL_INTERVAL_SECONDS` (по умолчанию 300с = 5 мин).
- **Курсор**: на каждый канал хранится `last_message_id` — следующий опрос запрашивает только сообщения новее последнего увиденного (`get_messages(min_id=...)`), без повторов.
- **Релевантность**: канал — это "мешанина" разных постов, поэтому для каждого сообщения определяется релевантность и язык(и) через `processing/languages.py::detect_languages()` (то же, что используется для HH/LinkedIn, но там язык уже известен из поискового запроса, а здесь — определяется по тексту).
- **Доставка**: вакансии из Telegram-каналов пересылаются подписчику как **оригинальное сообщение** (`forward_message`), не переформатированным текстом — так решили специально, чтобы не терять оформление оригинала. Если форвард не удался (бот физически не состоит в канале, откуда это читал Telethon-аккаунт), есть fallback на обычную отправку сырого текста, чтобы вакансия не терялась молча.

## Поддерживаемые языки/треки и теги стека

Единый реестр для всех источников — `src/jobsbot/processing/languages.py` (ключевые слова для релевантности + поисковый термин на HH) и `src/jobsbot/processing/stack_tags.py` (фреймворки/БД/инфра-теги). Полная таблица — [`docs/languages-and-stacks.md`](languages-and-stacks.md); не дублируется здесь, чтобы не разъезжалось при добавлении нового языка.

## Дедупликация

Один и тот же пост может прийти из нескольких источников (например, компания опубликовала вакансию и на hh.ru, и в Telegram-канале). Дедуп — по sha256-фингерпринту нормализованного `title + company + description` (`processing/dedup.py`), единый для всех источников, выполняется в `processing/pipeline.py::ingest()` перед вставкой в БД.
