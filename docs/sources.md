# Источники вакансий

Бот собирает вакансии из трёх источников. Все три работают через **поллинг** (периодический опрос), управляются одним `AsyncIOScheduler` в `src/jobsbot/main.py`.

## 1. HH.ru

- **Как собирается**: HTML-парсер страницы поиска `hh.ru/search/vacancy` (`src/jobsbot/ingestion/hh_adapter.py`) — **не официальный API** (он платный для такого использования), обычный HTTP-запрос с теми же параметрами, что видит браузер.
- **Описание вакансии**: страница поиска не отдаёт описание — оно дотягивается отдельным запросом на страницу вакансии (`fetch_description`), но **только для новых** вакансий, прошедших дедуп и фильтр релевантности (чтобы не плодить лишние запросы на весь список выдачи).
- **Интервал**: `HH_POLL_INTERVAL_SECONDS` (по умолчанию 600с = 10 мин).
- **Языки**: отдельный поисковый запрос на **каждый** язык из реестра `processing/languages.py` (см. список ниже) — т.е. за один цикл поллинга бот делает N запросов к hh.ru, один на язык.
- **Легальность**: публичная HTML-страница, без логина, с паузами между запросами (`PAGE_DELAY_SECONDS`).

## 2. LinkedIn

- **Как собирается**: публичный неавторизованный "guest"-эндпоинт поиска вакансий (`src/jobsbot/ingestion/linkedin_adapter.py`) — без логина, без cookies/сессии.
- **Статус**: выключен по умолчанию (`LINKEDIN_ENABLED=false`). Самый изолированный и юридически рискованный источник в проекте — LinkedIn жёстче, чем hh.ru, борется со скрапингом. Включается одним флагом в `.env`, выключается так же мгновенно, не затрагивая остальные источники.
- **Интервал**: `LINKEDIN_POLL_INTERVAL_SECONDS` (по умолчанию 3600с = 1 час) — заметно реже HH, плюс случайные задержки и экспоненциальный backoff между запросами.
- **Языки**: только Python (`language_hint="python"` жёстко зашит в `main.py::poll_linkedin()`), мультиязычность на LinkedIn не распространяется — осознанное ограничение скоупа.
- **Описание**: не дотягивается (в отличие от HH) — фильтр по стеку для LinkedIn-вакансий работает только если технология упомянута в заголовке.

## 3. Telegram-каналы

- **Как собирается**: `src/jobsbot/ingestion/telegram_poller.py`, через Telegram **user-аккаунт** (библиотека Telethon, MTProto) — обычный бот не может сам вступать в чужие публичные каналы, поэтому используется отдельная авторизация по номеру телефона (один раз, создаёт `.session`-файл).
- **Список каналов — хранится в БД**, не в `.env`. Управляется через `/admin` → "📡 Каналы" (см. [`admin.md`](admin.md)) — добавление/удаление происходит без передеплоя и подхватывается на следующем цикле поллинга.
- **Интервал**: `TELEGRAM_POLL_INTERVAL_SECONDS` (по умолчанию 300с = 5 мин).
- **Курсор**: на каждый канал хранится `last_message_id` — следующий опрос запрашивает только сообщения новее последнего увиденного (`get_messages(min_id=...)`), без повторов.
- **Релевантность**: канал — это "мешанина" разных постов, поэтому для каждого сообщения определяется релевантность и язык(и) через `processing/languages.py::detect_languages()` (то же, что используется для HH/LinkedIn, но там язык уже известен из поискового запроса, а здесь — определяется по тексту).
- **Доставка**: вакансии из Telegram-каналов пересылаются подписчику как **оригинальное сообщение** (`forward_message`), не переформатированным текстом — так решили специально, чтобы не терять оформление оригинала. Если форвард не удался (бот физически не состоит в канале, откуда это читал Telethon-аккаунт), есть fallback на обычную отправку сырого текста, чтобы вакансия не терялась молча.

## Поддерживаемые языки программирования

Единый реестр для всех источников — `src/jobsbot/processing/languages.py`. Для каждого языка: ключевые слова для определения релевантности текста и поисковый термин для HH.

| Язык | Ключ | Поисковый термин на HH.ru |
|---|---|---|
| Python | `python` | `python` |
| JavaScript/TypeScript | `javascript` | `javascript` |
| Go | `go` | `golang` |
| Java | `java` | `java` |
| C#/.NET | `csharp` | `c#` |
| PHP | `php` | `php` |
| Ruby | `ruby` | `ruby` |

Полный список фреймворков/инструментов под каждый язык + универсальные инфраструктурные теги (PostgreSQL, MySQL, MongoDB, Redis, RabbitMQ, Kafka, Docker/K8s) — в `src/jobsbot/processing/stack_tags.py`; пользователь выбирает их в боте через `/stack`.

## Дедупликация

Один и тот же пост может прийти из нескольких источников (например, компания опубликовала вакансию и на hh.ru, и в Telegram-канале). Дедуп — по sha256-фингерпринту нормализованного `title + company + description` (`processing/dedup.py`), единый для всех источников, выполняется в `processing/pipeline.py::ingest()` перед вставкой в БД.
