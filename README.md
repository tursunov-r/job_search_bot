# jobsbot

Telegram-бот, который собирает вакансии разработчиков (Python, JavaScript/TypeScript, Go, Java, C#/.NET, PHP, Ruby и другие — см. [`docs/languages-and-stacks.md`](docs/languages-and-stacks.md)) с hh.ru, Хабр Карьеры, Geekjob.ru, LinkedIn и публичных Telegram-каналов, и присылает подписчикам только то, что реально совпадает с их языком и стеком (Django, Redis, Kafka и т.п.) — выбирается в самом боте через кнопку «➕ Добавить стек». Рассылку подписчик включает и выключает сам кнопками «👀 Смотреть вакансии» / «⏸ Остановить рассылку». Монетизация — отдельные баннерные рекламные рассылки, не вмешанные в сами вакансии.

Рассчитан на запуск на **Raspberry Pi** (через Docker), чтобы не платить за VPS.

## Быстрый старт (Docker)

Нужен Docker и docker-compose. Предполагается 64-битная ОС (на Raspberry Pi — Raspberry Pi OS 64-bit или Ubuntu Server arm64).

```bash
git clone <repo> && cd project_alpha
cp .env.example .env
# заполнить .env (см. таблицу переменных ниже) — как минимум BOT_TOKEN,
# DB_PASSWORD, SUPER_ADMIN_TELEGRAM_USER_ID
```

```bash
docker compose up -d
```

Этого достаточно для парсинга **hh.ru** (и опционально LinkedIn) — Telegram-каналы без `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` в `.env` просто отключены (см. ниже), никакого дополнительного шага логина не нужно.

### Если нужен и парсинг Telegram-каналов

Заполни `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` в `.env` (как получить — см. [my.telegram.org/apps](https://my.telegram.org/apps)). Первый запуск после этого — **обязательно в интерактивном режиме**, не `-d`: Telethon попросит номер телефона и код из Telegram, чтобы создать `.session`-файл (это отдельный user-аккаунт для чтения каналов, не сам бот):

```bash
docker compose run --rm bot python -m jobsbot.main
# ввести номер телефона, затем код из Telegram
# после того как в логах пошёл обычный поллинг — Ctrl+C
docker compose up -d   # дальше обычный запуск в фоне, .session сохранён в ./data
```

Проверить, что всё поднялось:

```bash
docker compose ps                 # оба сервиса должны быть Up / healthy
docker compose logs -f bot        # живые логи поллинга
```

### Перезапуск / обновление

Просто перечитать `.env` (без пересборки — если менял только переменные окружения):

```bash
docker compose restart bot
```

После `git pull` с новым кодом — пересобрать образ и пересоздать контейнер:

```bash
git pull
docker compose up -d --build
```

Если нужно руки полностью пересоздать контейнеры (например, что-то зависло):

```bash
docker compose down
docker compose up -d
```

`postgres` при этом не трогается — данные в volume `pgdata` сохраняются; `down -v` вместо `down` **удалит и данные БД**, так делать не нужно без явной необходимости всё стереть.

Все шаги выше (git pull → down → build --no-cache → up) одной командой — скрипт [`deploy.py`](deploy.py):

```bash
python3 deploy.py
```

Скрипт останавливается на первом шаге, который завершился с ошибкой, и печатает код выхода — так что если что-то упало, видно сразу на каком этапе.

**Безопасно гонять по расписанию**: скрипт делает `git pull`, сравнивает коммит до/после, и если ничего нового — тихо завершается, не трогая работающие контейнеры. Пересборка/перезапуск происходит только если реально пришли изменения. Это специально, чтобы можно было поставить в `crontab` и не зависеть от того, с какого IP/сети физически запускать деплой:

```cron
*/5 * * * * cd /home/pi/telegram_bot/job_search_bot && python3 deploy.py >> deploy.log 2>&1
```

### Миграции схемы БД (Alembic)

Миграции накатываются **автоматически при каждом запуске** бота (`storage/db.py::init_db()` вызывает `alembic upgrade head` перед стартом) — руками ничего делать не нужно, в том числе на уже работающем деплое: если в коде появилась новая миграция, она применится сама на следующем перезапуске контейнера (`python3 deploy.py` или `docker compose up -d --build`), а если база уже на последней версии — это просто no-op.

Как добавить новую миграцию (для разработки):

```bash
# после изменения моделей в storage/models.py
alembic revision --autogenerate -m "краткое описание изменения"
# проверить сгенерированный файл в alembic/versions/ — autogenerate не всегда
# угадывает верно (переименования колонок, сложные constraint'ы и т.п.)
```

Закоммитить получившийся файл из `alembic/versions/` вместе с изменением модели — на следующем деплое миграция применится сама.

### Полный перепарсинг вакансий (после фикса парсера)

Если в адаптере источника был баг и в БД уже накопились вакансии с неверными/пустыми полями — [`reset_vacancies.py`](reset_vacancies.py) удаляет все вакансии из БД и парсит их заново уже исправленным кодом. Подписчикам ничего не рассылается повторно — курсор каждого подписчика просто переставляется на самую свежую перепарсенную вакансию ("уже видел", а не "заново всё с нуля").

Запускать внутри контейнера бота на самой Raspberry Pi:

```bash
docker compose exec bot python reset_vacancies.py
```

Перепарсивает hh.ru, Хабр Карьеру, Geekjob.ru и LinkedIn (если включён) — Telegram-каналы не затрагиваются, их поллер читает только новые сообщения после сохранённого курсора, а не историю.

### Рассылка новых вакансий в топики группы

Помимо личных сообщений подписчикам, новые вакансии можно постить в топики форума Telegram-группы — по одному топику на язык/трек (несколько языков могут указывать на один и тот же топик, например все мобильные — в один топик "Mobile"). Это отдельная, не завязанная на личные фильтры подписчиков рассылка: туда попадает **каждая** новая вакансия подходящего языка.

Настройка:
1. `GROUP_CHAT_ID` в `.env` — id группы для Bot API. Для приватной супергруппы это `-100` + числовой id из ссылки на топик (`https://t.me/c/<id>/<thread_id>`) — например, `id=3880476487` → `GROUP_CHAT_ID=-1003880476487`.
2. Бот должен быть добавлен в группу с правом писать сообщения.
3. Соответствие "язык → топик" — в БД (таблица `group_topics`), не в `.env`, по той же логике, что и Telegram-каналы (меняется без передеплоя). Текущее соответствие задано в [`seed_group_topics.py`](seed_group_topics.py) — отредактировать словарь `TOPICS` там и перезапустить:

```bash
docker compose exec bot python seed_group_topics.py
```

Если `GROUP_CHAT_ID` не задан или в `group_topics` нет ни одной записи — рассылка в группу просто не запускается, на личные сообщения подписчикам это не влияет.

**После первого включения** (или после добавления топика под новый язык) накопившийся исторический бэклог вакансий **не** рассылается — вместо этого он сразу помечается как "уже отправлено", без реальной отправки, и дальше в топики попадают только по-настоящему новые вакансии:

```bash
docker compose exec bot python backfill_group_topic_baseline.py
```

Без этого шага бот попытается разослать весь накопленный бэклог целиком — упрётся в лимит Telegram на сообщения в чат (общий для всех топиков одной группы) и будет медленно, неравномерно догонять его циклами, заодно заваливая группу старыми неактуальными вакансиями.

### Резюме и интервью (Gemini)

Две кнопки, обе работают по одной схеме: подписчик присылает резюме (PDF/TXT/MD) → бот отправляет его в Gemini с соответствующим промптом → присылает обратно `.md`-файл. Резюме и ответ Gemini **не сохраняются ни в БД, ни на диске** — всё держится в памяти процесса и живёт ровно один запрос.

- **🎯 Подготовка к интервью** ([`docs/gemini_promts/interview_prep.md`](docs/gemini_promts/interview_prep.md)) — только реальные достижения из резюме, разложенные по STAR, без выдуманных причин смены работы или фиктивных "факапов".
- **✨ Улучшить резюме** ([`docs/gemini_promts/resume_improve.md`](docs/gemini_promts/resume_improve.md)) — усиливает формулировки и может добавить ориентировочную метрику там, где кандидат описал результат без цифры ("сократил время выполнения ориентировочно на 20–30%"), но не придумывает новые компании/проекты/технологии, которых не было в оригинале, и отдельно перечисляет, где метрика иллюстративная, а не точный замер.

Если нужен другой тон или акценты — правь сам файл промпта в `docs/gemini_promts/`, передеплоя не нужно (промпт читается из файла при старте).

Нужен только `GEMINI_API_KEY` в `.env` (ключ — на [aistudio.google.com/apikey](https://aistudio.google.com/apikey), у Gemini есть бесплатный тариф). Без ключа обе кнопки просто не показываются в меню подписчика.

## Локальный запуск без Docker (для разработки)

Нужен Python 3.11+ и запущенный где-то Postgres (например, `docker run -d -e POSTGRES_PASSWORD=... -p 5432:5432 postgres:16-alpine`).

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
cp .env.example .env   # заполнить, DB_HOST=localhost если Postgres локально
python -m jobsbot.main
```

Тесты (не требуют БД — чистая логика):

```bash
pip install -e ".[dev]"
PYTHONPATH=src pytest tests/ -v
```

## Что не настраивается через `.env`

Сознательно вынесено в саму БД/бота, не в конфиг — потому что должно меняться без передеплоя:

- **Список Telegram-каналов для парсинга** — через `/admin` → "📡 Каналы" (не переменная окружения).
- **Сотрудники и их права** — через `/admin` → "👥 Сотрудники".
- **Язык/стек, город, формат работы, старт/стоп рассылки** — через reply-keyboard меню подписчика в самом боте (кнопки «➕ Добавить стек» / «🏙 Город» / «🧭 Формат работы» / «👀 Смотреть вакансии» / «⏸ Остановить рассылку»). Город не задан = вакансии из всех городов; формат не задан = любой формат; удалённые вакансии проходят фильтр по городу независимо от того, какой город указан.

## Структура проекта

```
src/jobsbot/
  main.py              — точка входа, сборка планировщика и бота
  config.py            — настройки из .env (pydantic-settings)
  bot/                 — aiogram: диспетчер, хендлеры команд, права, пуш вакансий
  ingestion/           — адаптеры источников (hh.ru, LinkedIn, Telegram-поллер)
  processing/          — дедуп, фильтр релевантности по языкам, теги стека
  ads/                 — рекламные кампании
  storage/             — модели SQLModel, доступ к БД
tests/                 — юнит-тесты (чистая логика, без БД/сети)
docs/                  — стек, источники, админка (см. выше)
Dockerfile, docker-compose.yml
```
